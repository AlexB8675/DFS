# DFS — Discord File System

A private cloud drive that stores encrypted file chunks as Discord attachments and
keeps the real file system in PostgreSQL. See [docs/DESIGN.md](docs/DESIGN.md) for
the full design.

**Status:** the web UI is done, built first against an in-browser mock API (D14).
The backend is under way: the foundations (M0) are in place, and the API's features
come next. [docs/BACKEND.md](docs/BACKEND.md) is the build plan.

## Requirements

- Node.js 24
- Docker Desktop, for PostgreSQL and the integration tests
- pnpm 10, via Corepack. Turborepo runs each package's scripts with `pnpm`, so
  `pnpm` itself must be on your PATH; `corepack pnpm …` alone is not enough.
  Set it up once:

  ```bash
  corepack enable pnpm
  ```

  If that fails because Node is installed in a protected folder, put the shims
  in a folder that is on your PATH instead, e.g. npm's global folder on Windows:
  `corepack enable pnpm --install-directory "$env:APPDATA\npm"` (PowerShell).

## Getting started

```bash
pnpm install
pnpm dev
```

Open http://localhost:5173 and sign in with one of the demo accounts listed under
the form; clicking one fills it in. `demo` is the owner and an admin, and `taylor`
shows a first sign-in, where a new user chooses their own password. In development
all data lives in your browser (reset it from the account menu).

The demo data includes share links to try, signed in or not:

| Link                | What it shows                          |
| ------------------- | -------------------------------------- |
| `/s/demo-documents` | A folder to browse and download        |
| `/s/demo-lisbon`    | A password-protected folder (`lisbon`) |
| `/s/demo-resume`    | A single file with a download limit    |
| `/s/demo-expired`   | An expired link                        |
| `/s/demo-revoked`   | A link the owner turned off            |

## Running the backend

`pnpm dev` also starts the API (http://localhost:3000) and the bot (port 3001).
They need PostgreSQL, which runs in Docker:

```bash
pnpm db:up
pnpm db:migrate
pnpm dev
```

Without the database, both still start: `/api/health` answers 503 and the bot
retries until Postgres is up. Settings go in a `.env` file at the root (copy
`.env.example`); in development every one of them has a working default. To run
only the web app, use `pnpm --filter @dfs/web dev`.

The UI still uses its mock API; it switches to the real one in M2.

## Scripts

Run from the repository root; Turborepo runs them in every package.

| Command           | What it does                                                    |
| ----------------- | --------------------------------------------------------------- |
| `pnpm dev`        | Starts the web app (with its mock API), the API and the bot     |
| `pnpm check`      | Formatting, typecheck, lint and tests: run it before every push |
| `pnpm build`      | Production build of the web app                                 |
| `pnpm typecheck`  | TypeScript checks                                               |
| `pnpm lint`       | ESLint, including the React Compiler rules                      |
| `pnpm test`       | Unit and integration tests (Vitest); the latter need Docker     |
| `pnpm format`     | Formats with Prettier                                           |
| `pnpm db:up`      | Starts PostgreSQL 18 in Docker, on localhost only               |
| `pnpm db:down`    | Stops it; the data stays in a Docker volume                     |
| `pnpm db:migrate` | Applies database migrations                                     |

Integration tests start their own PostgreSQL in Docker. Without Docker, point
`TEST_DATABASE_URL` at a server where the user may create databases.

## Layout

```
apps/web          React SPA (React 19 + React Compiler, Vite, Tailwind, shadcn/ui)
  src/app         router, query client, providers
  src/features    one folder per feature: auth, drive, drag, tree, uploads, live-events, admin, …
  src/layout      app shell: header, sidebar
  src/components  shared components; ui/ is generated by shadcn
  src/mocks       mock API (MSW) and demo data, dev only
apps/api          Fastify HTTP API, run by Node straight from its TypeScript sources
apps/bot          job workers and leader election (Discord comes in M1)
packages/shared   API schemas (Zod) and file-name rules, shared by the web app and the API
packages/config   settings from the environment, with development defaults
packages/db       Drizzle schema, SQL migrations, and the integration test harness
docker/           PostgreSQL for development
docs/DESIGN.md    design document
docs/BACKEND.md   backend build plan
```
